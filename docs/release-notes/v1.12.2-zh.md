# CPA Manager Plus v1.12.2

> Draft

> [English ->](https://github.com/seakee/CPA-Manager-Plus/blob/v1.12.2/docs/release-notes/v1.12.2-en.md)

## Overview

本补丁修复 [#563](https://github.com/seakee/CPA-Manager-Plus/issues/563) 暴露的升级可运维性问题：v1.12.0 为保证大型历史数据库 listener-first 启动，会延后非空大表索引和部分派生清理；此前 Manager Server 能正常监听，但用户只能从日志发现数据库仍处于查询性能降级状态。v1.12.2 将该状态正式建模并通过 `/status`、全局 Warning、系统信息和请求监控页展示，同时保留 v1.12.0 的 bounded startup 边界。

## Highlights

### Features

- `GET /status` 新增脱敏的 `databaseMaintenance` 状态，报告是否需要维护、是否可能影响查询性能、deferred index 数量、offline cleanup job 数量、稳定 reason code 和 `cleanup-derived` 命令提示；`?scope=database-maintenance` 为全局提示提供 metadata-bounded 轻量读取（`manager-server/sqlite`、`manager-server/system`）。
- Manager Server 托管面板会在数据库维护未完成时显示全局 Warning，并提供可折叠的 Docker Compose 和原生维护步骤；系统信息页同步显示维护计数（`web/layout`、`web/system-info`）。
- 请求监控页会在查询前提示历史请求可能较慢或超时；选择 7 天、14 天、30 天、全部或至少 7 天的自定义范围时追加长窗口软提示，但不会阻止查询或改变查询语义（`web/monitoring`）。

### Fixes

- 修复 deferred indexes / offline derived cleanup 只写日志、导致 HTTP 和 health 看似正常但 Request Monitoring 可能执行昂贵扫描与临时排序的问题（`manager-server/status`、`web`）。
- deferred index 决策会持久化到有界 metadata ledger，并与 SQLite schema、derived cleanup 和 quota migration metadata 一起计算；即使派生表被后台暂时清空，也不会错误隐藏仍缺失的索引，运行 `cleanup-derived` 并重启后仍会自动恢复 clean（`manager-server/sqlite`）。
- 超大旧 quota snapshot group 会标记为 `offline_required`，并兼容识别 v1.12.0 已写入的对应 `failed` 标记，使该维护要求纳入 `offlineJobs`，不再从 `/status` 漏报（`manager-server/quota`、`manager-server/sqlite`）。
- 凭证管理的 account-history 最近请求读取改为按凭证执行有界 top-N 索引查询，完整使用 `auth file/source + auth_index + timestamp` 复合索引，避免 maintenance 完成后仍对单个凭证的全部历史做窗口排序（`manager-server/usage-event`）。
- `databaseMaintenance` 对象不新增数据库绝对路径、原始 SQL、索引名称或底层迁移错误详情；完整 `/status` 保留既有字段以维持兼容（`manager-server/system`）。

### Performance

- 新增 100k request-monitoring projection 回归测试：正确 timestamp index 存在时查询使用 covering index；缺索引时 `EXPLAIN QUERY PLAN` 会出现 `USE TEMP B-TREE FOR ORDER BY`，稳定覆盖 #563 的 planner 差异（`manager-server/monitoring`）。
- account-history query-plan 回归测试验证 snapshot 与 legacy source 分支都同时约束复合索引前两列，且不会 full-scan `usage_events`；最终排序只处理每个分支已限制的候选行（`manager-server/usage-event`）。
- 启动策略保持不变：不会在 listener 前对非空大表无条件执行 `CREATE INDEX`，也不会从 Web UI 在线运行离线清理（`manager-server/sqlite`、`web`）。

### Docs

- 中英文 Manager Server、Docker 和更新文档补充 maintenance 状态说明、完整 Docker Compose / 原生命令、停服务原因和 `usage_events` 数据安全边界。

## Upgrade Notes

- 升级前请一起备份 SQLite、WAL、SHM 和 `data.key`。Manager Server 会先监听 HTTP，再继续有界后台迁移。
- 如果 UI Warning 或 `/status.databaseMaintenance.required` 为 `true`，Docker Compose 用户执行：

```bash
docker compose stop cpa-manager-plus

docker compose run --rm --no-deps \
  cpa-manager-plus \
  cleanup-derived --db-path /data/usage.sqlite

docker compose start cpa-manager-plus
```

- 原生安装使用 `cpa-manager-plus cleanup-derived`；非默认数据库可追加 `--db-path /path/to/usage.sqlite`。
- 必须先停止 Manager Server，离线命令需要独占 SQLite 进程锁。Web UI 不会自动执行 cleanup。
- `cleanup-derived` 不会删除、重建或改写 authoritative `usage_events`。完成并重启后，维护状态和 UI Warning 会自动恢复正常。
