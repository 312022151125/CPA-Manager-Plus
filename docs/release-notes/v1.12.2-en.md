# CPA Manager Plus v1.12.2

> Draft

> [中文 ->](https://github.com/seakee/CPA-Manager-Plus/blob/v1.12.2/docs/release-notes/v1.12.2-zh.md)

## Overview

This patch fixes the upgrade-operability gap reported in [#563](https://github.com/seakee/CPA-Manager-Plus/issues/563). v1.12.0 keeps large historical databases listener-first by deferring populated-table indexes and some derived cleanup. Previously Manager Server could listen normally while users had no product-visible indication that query performance remained degraded. v1.12.2 formally models that state and exposes it through `/status`, a global warning, System Info, and Request Monitoring while preserving the v1.12.0 bounded-startup boundary.

## Highlights

### Features

- Add a sanitized `databaseMaintenance` object to `GET /status`, reporting whether maintenance is required, whether query performance may be degraded, deferred-index and offline-job counts, stable reason codes, and the `cleanup-derived` command hint. The `?scope=database-maintenance` view gives the global warning a metadata-bounded read (`manager-server/sqlite`, `manager-server/system`).
- Show a global warning in the Manager Server-hosted panel with collapsible Docker Compose and native maintenance steps, and show the same bounded counts in System Info (`web/layout`, `web/system-info`).
- Warn in Request Monitoring before a degraded historical query runs. Selecting 7-day, 14-day, 30-day, all-history, or custom ranges of at least seven days adds a long-range soft warning without blocking the query or changing its semantics (`web/monitoring`).

### Fixes

- Fix the state where deferred indexes or offline derived cleanup appeared only in logs, leaving HTTP and health apparently normal while Request Monitoring could perform expensive scans and temporary sorts (`manager-server/status`, `web`).
- Persist deferred-index decisions in a bounded metadata ledger and combine them with SQLite schema, derived-cleanup, and quota-migration metadata on every read. This prevents a temporarily emptied derived table from incorrectly hiding a still-missing index, while `cleanup-derived` and restart still return the state to clean automatically (`manager-server/sqlite`).
- Mark oversized legacy quota-snapshot groups as `offline_required`, and recognize the matching v1.12.0 `failed` marker for upgrade compatibility, so this cleanup requirement is included in `offlineJobs` instead of being omitted from `/status` (`manager-server/quota`, `manager-server/sqlite`).
- Make the Accounts account-history latest-request reader perform bounded per-credential top-N index queries that fully use the `auth file/source + auth_index + timestamp` composite indexes, avoiding a window sort over a credential's entire history even after maintenance is complete (`manager-server/usage-event`).
- Add no absolute database path, raw SQL, index names, or low-level migration errors to `databaseMaintenance`; the full `/status` response retains its existing fields for compatibility (`manager-server/system`).

### Performance

- Add a 100k request-monitoring projection regression test. With the timestamp index, the query uses the covering index; without it, `EXPLAIN QUERY PLAN` reports `USE TEMP B-TREE FOR ORDER BY`, covering the planner difference behind #563 without flaky millisecond assertions (`manager-server/monitoring`).
- Add an account-history query-plan regression that verifies both snapshot and legacy-source branches constrain the first two composite-index columns and never full-scan `usage_events`; the final sort sees only the already limited branch candidates (`manager-server/usage-event`).
- Preserve listener-first startup: Manager Server does not unconditionally create populated-table indexes before listening, and the web UI never runs offline cleanup online (`manager-server/sqlite`, `web`).

### Docs

- Update the Chinese and English Manager Server, Docker, and upgrade guides with maintenance-state semantics, complete Docker Compose and native commands, the stop-service requirement, and the `usage_events` safety boundary.

## Upgrade Notes

- Back up SQLite, WAL, SHM, and `data.key` together before upgrading. Manager Server binds HTTP first and continues bounded background migration afterwards.
- If the UI warning or `/status.databaseMaintenance.required` is `true`, Docker Compose users should run:

```bash
docker compose stop cpa-manager-plus

docker compose run --rm --no-deps \
  cpa-manager-plus \
  cleanup-derived --db-path /data/usage.sqlite

docker compose start cpa-manager-plus
```

- Native installations use `cpa-manager-plus cleanup-derived`; append `--db-path /path/to/usage.sqlite` for a non-default database.
- Stop Manager Server first because the offline command requires the exclusive SQLite process lock. The web UI never runs cleanup automatically.
- `cleanup-derived` never deletes, rebuilds, or rewrites authoritative `usage_events`. After completion and restart, the status and UI warning return to normal automatically.
